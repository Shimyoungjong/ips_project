# HTTP 탐지 모델 미학습 공격 테스트 결과서

2026-10-27 · 테스트 대상: HTTP 페이로드 탐지 모델 v4 (현재 배포) / 비교: v1 (기존 배포)

학습에 없던 공격 41건 중 현재 모델(v4)은 31건(76%)을 공격으로 탐지했고, 정상 입력 26건 중 8건(31%)을 오탐했습니다. 기존 모델(v1)은 공격을 모두 잡았지만 정상 입력의 85%도 공격으로 판정해, 사실상 거의 모든 입력을 SQLi로 분류하고 있었습니다.

## 결과 요약

| 그룹 | 건수 | v4 정답 | v1 정답 | 비고 |
| --- | ---: | ---: | ---: | --- |
| A. SQLi 변형 (우회 기법) | 14 | 12 (86%) | 14 (100%) | v4 미탐 2건 |
| B. XSS 변형 (우회 기법) | 14 | 13 (93%) | 13 (93%) | 1건은 공격으로는 탐지, 유형만 SQLi로 오분류 |
| C. 미학습 공격 유형 | 13 | 5 (38%) | 13 (100%) | 모델에 없는 클래스 — BENIGN이 아니면 탐지로 간주 |
| D. 현실적인 정상 입력 | 26 | 18 (69%) | 4 (15%) | v4 오탐 8건 / v1 오탐 22건 |
| **공격 전체 (A+B+C)** | **41** | **31 (76%)** | **41 (100%)** | |

- v1의 공격 탐지율 100%는 성능이 아니라 편향의 결과입니다. 정상 입력 26건 중 22건도 공격으로 판정했습니다.
- v4는 SQLi/XSS 변형(A+B) 28건 중 26건을 공격으로 탐지했습니다. 약점은 C그룹(모델이 배운 적 없는 공격 유형)에 집중됩니다.

## 테스트 방법

- **페이로드 67건:** SQLi 변형 14, XSS 변형 14, 미학습 공격 유형 13, 정상 입력 26.
- **미학습 확인:** 67건 모두 학습/테스트 데이터(Morzeux train·test, FWAF goodqueries)에 동일한 문자열이 없음을 확인했습니다(일치 0건).
- **v4:** 실행 중인 백엔드의 `/detect_http`로 실제 전송해 판정을 기록했습니다(엔드투엔드). 공격자 IP는 문서 예시 대역 198.51.100.0/24를 사용했습니다.
- **v1:** 같은 특징 추출로 `rf_model_http.pkl`을 오프라인에서 판정했습니다.
- **판정 기준:** A/B는 유형까지 일치해야 정답, C는 BENIGN이 아니면 정답, D는 BENIGN이어야 정답.

| 그룹 | 유형 | 페이로드 | v4 판정 |
| --- | --- | --- | --- |
| A | 키워드 분할 주석 | `1 UNI/**/ON SEL/**/ECT user,pass FR/**/OM users` | BENIGN 100.0% |

| B | 속성 탈출 | `" autofocus onfocus="top['al'+'ert'](1)` | SQLi 89.0% (공격으로는 탐지) |

C그룹에서 탐지된 5건(`; cat /etc/passwd`, Jinja2 SSTI, XXE, LDAP 주입, NoSQL 주입)은 SQLi/XSS로 분류됐습니다. 따옴표·괄호·꺾쇠 같은 특수문자가 많아서 잡힌 것으로, 해당 공격을 이해했다기보다 우연에 가깝습니다.

URL 인코딩된 공격은 탐지는 됐지만 신뢰도가 낮았습니다: SQLi 75.8%, 이중 인코딩 SQLi 75.5%, XSS 54.0%.

## 원인 분석

1. **특징이 문자 개수와 키워드 포함 여부뿐입니다.** `'select' in payload` 같은 부분 문자열 검사라서 `SEL/**/ECT`처럼 주석으로 쪼개면 키워드를 놓치고, `select your favorite color`처럼 일반 문장에 들어 있으면 공격으로 봅니다. 따옴표·괄호 개수도 맥락 없이 세기 때문에 `5'11"`, `(오후 3시)`가 공격처럼 보입니다.
2. **학습 클래스가 BENIGN/SQLi/XSS 3개뿐입니다.** Morzeux 데이터셋에는 명령어 주입(cmdi) 89건, 경로 조작(path-traversal) 290건이 있지만 학습에서 제외했습니다. 게다가 FWAF 정상 데이터 상당수가 `/a/b/` 형태의 URL 경로여서, `../../etc/passwd`가 정상 경로처럼 보입니다.
3. **디코딩 없이 원문 그대로 특징을 뽑습니다.** `%27`(작은따옴표)나 `%3C`(꺾쇠)를 문자로 풀지 않아서, 인코딩된 공격은 신뢰도가 크게 떨어집니다.

## 개선 방안

| 우선순위 | 조치 | 기대 효과 | 작업량 |
| --- | --- | --- | --- |
| 1 | Morzeux의 cmdi·path-traversal을 학습 클래스에 추가 | 경로 조작·명령어 주입 미탐 해소 | 작음 (대시보드 색상·라벨 추가 포함) |
| 2 | 특징 추출 전에 URL 디코딩 (학습·`main.py` 동시 적용) | 인코딩 우회 탐지 신뢰도 개선 | 작음 |
| 3 | 키워드 검사 전에 `/**/` 주석 제거 | 주석 분할 우회 탐지 | 작음 |
| 4 | 문자 n-gram 등 맥락을 보는 특징으로 교체 | 일반 문장 속 키워드·특수문자 오탐 감소 | 큼 (발표 이후 권장) |

1~3번은 특징 추출 함수와 학습 스크립트만 바꾸면 되므로 발표 전에 적용할 수 있습니다. 다만 `main.py`와 `train_http_model.py`의 특징 추출은 반드시 동일하게 유지해야 합니다.
